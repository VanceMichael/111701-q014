# 大学资助机会采集服务

这是一个用于大学资助机会的本地数据采集与归档服务。当前版本从仓库自带的合成来源记录读取一页数据，经过字段规整后写入进程内目录；来源内容和规整后的记录保留独立边界，便于在不访问外部系统的情况下复现采集过程。

基金机构的**补充通知**与来源页分开存放（`data/notices.json`）：通知只记录“改了什么”，不写回原页面，因此机构当初发布的内容始终保持原样。通知通过强标识（`source` + `id`，或机构的 `agency` + `externalId`）绑定到唯一项目；无法唯一对应时直接报错，不会按名称或相似度猜测。

## 三条不变量

1. **通知落到正确项目**：通知在接收时就绑定到目录中的一个项目，之后的修订不能改投到另一个项目。没有通知文件是合法状态。
2. **保存的筛选结果重新判断**：`ScreenStore` 只保存筛选条件，求值时总是用“当前目录 + 给定日期上有效的通知”重算，并给出相对上次结果的 `added` / `removed` / `changed`。`updateCriteria`（人改了条件）与 `reevaluate`（条件不变、外部规则变了）分开记录。
3. **已发提醒保留当时规则**：`AlertLog` 在发送时按值冻结筛选条件、当日有效条件、所依据的通知及其修订号和哈希。之后通知被修正或页面更新，`explain()` 仍返回发送时的依据；如需说明“今天是否还推荐”，用 `compareWithCurrent()` 单独对比，不覆盖原快照。

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
npm run demo     # 完整链路演示，输出 JSON
node src/pipeline.mjs
```

测试使用项目内的合成记录；执行不需要网络、凭据或外部服务。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/source.mjs` | 读取来源页与补充通知文件 |
| `src/opportunity.mjs` | 校验日期、资格、外部编号等基础事实 |
| `src/catalog.mjs` | 合并多页来源、维护项目身份、解析通知引用 |
| `src/notices.mjs` | 补充通知校验、取代关系、按日期计算有效条件 |
| `src/screening.mjs` | 保存筛选条件、求值、重算与差异 |
| `src/alerts.mjs` | 生成提醒、冻结规则快照、解释推荐依据 |

日期一律使用 `YYYY-MM-DD`；通知的 `effectiveFrom` 决定它从哪天起参与计算，早于该日期的历史判断不受影响。
